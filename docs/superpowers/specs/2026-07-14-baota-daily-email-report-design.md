# 宝塔错误与按量消费日报脚本设计

## 结论

新增一个独立 Bash 脚本 `deploy/baota-daily-email-report.sh`。脚本只通过现有 Sub2API 管理员 HTTP API 读取数据，使用 `x-api-key` 完成认证，不直接连接数据库，也不修改后端接口。SMTP/SMTPS 连接、HTML 邮件生成和发送全部由脚本完成。

日报固定统计北京时间前一自然日 `[00:00:00, 次日 00:00:00)`。即使没有错误和按量消费，也发送零数据日报。

## 范围

日报包含：

- 客户端最终失败请求。
- 请求最终成功、但处理中发生过故障转移的上游错误。
- 全部错误类型和错误状态聚合。
- 全部涉及错误的账号明细，不做 Top N 截断。
- `billing_type = 0` 且 `actual_cost > 0` 的真实余额扣费。
- 按账号套餐类型和分组/平台拆分的按量消费。

本任务不包含：

- 新增或修改后端 API。
- 直接查询 PostgreSQL、Redis 或其他内部存储。
- 修改现有项目内置运维定时报表。
- 在邮件中逐条列出全部原始错误事件或用量日志。
- 自动封禁、恢复账号或修改账号状态。

## 运行环境

脚本使用 Bash 4+，并依赖服务器已有命令：

- `curl`：请求管理员 API 和发送 SMTP 邮件。
- `jq`：解析 JSON、分页合并、关联和聚合。
- `base64`：编码 UTF-8 邮件主题。
- GNU `date`：计算北京时间前一自然日。
- `mktemp`：创建权限受限的临时目录。

脚本启动时逐项检查依赖和配置；缺失时立即退出，不发送部分日报，也不自动安装系统软件。

## 配置

宝塔定时任务通过环境变量传入配置：

| 变量 | 必填 | 说明 |
| --- | --- | --- |
| `SUB2API_BASE_URL` | 是 | Sub2API 基础地址，不带 `/api/v1` |
| `SUB2API_ADMIN_API_KEY` | 是 | 现有 `admin-` 管理员 API Key |
| `REPORT_TO` | 是 | 单个日报收件邮箱 |
| `SMTP_HOST` | 是 | SMTP 主机 |
| `SMTP_PORT` | 是 | SMTP 端口 |
| `SMTP_USERNAME` | 是 | SMTP 用户名 |
| `SMTP_PASSWORD` | 是 | SMTP 密码或授权码 |
| `SMTP_FROM` | 是 | 发件邮箱 |
| `SMTP_FROM_NAME` | 否 | 发件人名称，默认 `Sub2API Ops` |
| `SMTP_MODE` | 否 | `starttls`、`ssl` 或 `plain`，默认 `starttls` |

`REPORT_TO` 和 `SMTP_FROM` 必须通过邮箱格式和 CR/LF 检查。`SMTP_MODE` 只接受白名单值。脚本不打印 Admin API Key、SMTP 密码或带认证头的完整命令。

## API 数据源

所有请求使用请求头 `x-api-key: ${SUB2API_ADMIN_API_KEY}`，并校验 HTTP 状态、响应 JSON 的 `code == 0` 和预期 `data` 结构。

### 最终失败

分页请求：

```text
GET /api/v1/admin/ops/request-errors
```

参数包括：

- `start_time=<前一日 00:00:00+08:00>`
- `end_time=<当日 00:00:00+08:00>`
- `view=all`
- `page=<页码>`
- `page_size=500`

该端点保留客户端可见失败语义，即 `status_code >= 400`，并包含项目已有的 `cyber_policy` 例外。

### 上游错误

分页请求：

```text
GET /api/v1/admin/ops/upstream-errors
```

使用与最终失败相同的时间范围、`view=all` 和分页参数。该端点包含最终失败链路中的上游错误，也包含故障转移后请求成功的 recovered 上游错误。

### 按量用量

总额请求：

```text
GET /api/v1/admin/usage/stats
```

明细分页请求：

```text
GET /api/v1/admin/usage
```

共同参数包括：

- `start_date=<前一自然日>`
- `end_date=<当日>`
- `timezone=Asia/Shanghai`
- `billing_type=0`

明细额外使用 `exact_total=true` 和分页参数。脚本仍显式丢弃 `actual_cost <= 0` 的记录，以落实真实余额扣费口径。

### 账号资料

分页请求：

```text
GET /api/v1/admin/accounts
```

账号数据用于补充：

- 当前账号名称和状态。
- `credentials.plan_type`。
- 当前平台及分组信息。

API 已对敏感凭据做脱敏；脚本不保存或展示 token、上游 API Key 等敏感值。无法匹配的历史账号统一显示为“已删除/未知”。

## 分页和一致性

分页响应按 `data.items`、`data.page`、`data.pages` 和 `data.total` 处理。脚本持续读取到服务端声明的最后一页，并按日志 `id` 去重。任一核心页面失败、结构不符或出现异常空洞时，整次任务失败，不发送不完整邮件。

报表窗口已经结束，因此错误日志和用量日志在正常情况下应稳定。账号状态和套餐类型属于发送时的当前快照，不声称是请求发生时的历史快照。

## 错误分类

最终失败集合直接取自 `request-errors`。

上游错误使用以下关联键与最终失败集合匹配：

1. 非空 `request_id`。
2. `request_id` 为空时使用非空 `client_request_id`。
3. 两者都为空时只使用日志自身 `id`，不跨记录推断。

能够关联到最终失败请求的上游错误属于“最终失败链路”；不能关联到任何最终失败请求的上游错误属于“故障转移后成功”。该规则避免同一条上游错误同时计入两个主分类。

错误账号表以账号 ID 聚合；无账号 ID 的认证、路由前或平台错误单独归入“未绑定账号”。每个账号保留：

- 账号 ID、名称、套餐类型、分组、平台和当前状态。
- 最终失败请求数。
- 故障转移后成功前的上游错误数。
- 错误类型及次数。
- 错误状态码及次数。

全部错误事件参与聚合，全部不同错误账号进入账号表；不把每条原始错误消息逐行写入邮件。

## 消费口径

按量总额以 `usage/stats` 的 `total_actual_cost` 为权威总额，单位按 `1 余额 = 1 元` 展示。

明细日志用于生成两个拆分表：

- 按账号套餐类型：`plan_type`、请求数、实际扣费、金额占比。
- 按分组和平台：分组名称、平台、请求数、实际扣费、金额占比。

套餐类型为空或账号已删除时归为“未知类型”；分组为空时归为“未分组”。金额在计算过程中不提前舍入，邮件展示保留 6 位小数，占比保留 2 位小数。

脚本校验以下金额是否一致：

- `usage/stats` 总额。
- 全部明细日志求和。
- 套餐类型拆分求和。
- 分组拆分求和。

容差为 `0.000001`。超过容差时仍发送日报，但邮件主题和正文标记“数据校验异常”，并展示各口径差值。

## 邮件结构

邮件主题正常时为：

```text
[Sub2API 日报] YYYY-MM-DD 错误与按量消费
```

校验异常时增加前缀：

```text
[数据校验异常][Sub2API 日报] YYYY-MM-DD 错误与按量消费
```

HTML 正文依次包含：

1. 统计日期和北京时间范围。
2. 概览：最终失败数、recovered 上游错误数、错误账号数、按量请求数和按量总额。
3. 最终失败错误类型表。
4. recovered 上游错误类型表。
5. 最终失败状态码表。
6. recovered 上游状态码表。
7. 全部错误账号表。
8. 按套餐类型消费表。
9. 按分组/平台消费表。
10. 数据校验结果和生成时间。

零数据时仍生成完整结构，各区域显示 `0` 或“无数据”。所有来自 API 的文本在写入 HTML 前进行转义。

## SMTP 发送

脚本使用 `curl` 的 SMTP 支持发送 MIME HTML 邮件：

- `starttls`：使用 `smtp://` 并要求 TLS 升级。
- `ssl`：使用 `smtps://`。
- `plain`：使用未加密 `smtp://`。

中文主题采用 RFC 2047 Base64 编码，正文声明 `Content-Type: text/html; charset=UTF-8`。SMTP 凭据通过权限为 `0600` 的临时 curl 配置传递，避免直接出现在进程参数和普通日志中。

SMTP 发送不自动重试。连接已经接收邮件但响应丢失时，自动重试可能造成重复投递，因此失败由宝塔任务记录并由运维人员判断是否手工重跑。

## 安全和临时文件

- 脚本开头使用 `set -Eeuo pipefail`，不启用 `set -x`。
- 使用 `umask 077` 和 `mktemp -d` 创建临时目录。
- API Key、SMTP 配置、分页 JSON 和 MIME 邮件文件均位于临时目录，退出时通过 `trap` 删除。
- API Key 与 SMTP 密码不进入 URL、日志、邮件正文或错误摘要。
- 账号敏感凭据不进入临时聚合结果和邮件。
- 使用原子目录锁避免两个宝塔实例同时运行；锁只防并发，不阻止管理员之后手工重跑同一天日报。

## 失败处理

以下情况退出非零且不发邮件：

- 缺少依赖或必填环境变量。
- 邮箱、端口或 SMTP 模式无效。
- 管理员 API 鉴权失败。
- 核心 API 请求失败、超时或返回异常结构。
- 分页未完整拉取。
- HTML/MIME 生成失败。
- SMTP 发送失败。

单个历史账号无法匹配不是核心失败，按“已删除/未知”继续。金额校验异常也不阻断发送，但会在邮件中明确告警。

API GET 请求可对连接失败、超时和 HTTP 5xx 做有限重试；401、403、其他 4xx 和 JSON 业务错误不重试。SMTP 不重试。

## 宝塔执行方式

宝塔创建 Shell 脚本任务，设置所需环境变量后执行：

```bash
/bin/bash /path/to/sub2api/deploy/baota-daily-email-report.sh
```

建议每天北京时间早晨执行一次。脚本内部始终计算前一自然日，不依赖宝塔启动时刻是否恰好为整点。

## 验证

实现完成后执行：

- `bash -n deploy/baota-daily-email-report.sh`。
- 若本机存在 `shellcheck`，执行 ShellCheck；缺失时明确记录该验证未执行。
- 使用本地 HTTP fixture 模拟分页响应，验证多页合并、去重、API 错误和零数据。
- 验证最终失败与 recovered 上游错误的请求关联分类。
- 验证未知/已删除账号、套餐类型、分组和平台关联。
- 验证四组金额求和与容差告警。
- 使用本地 SMTP 捕获服务验证 MIME、中文主题和 HTML 正文。
- 检查标准输出和错误输出不包含测试 API Key 或 SMTP 密码。

验证不得调用正式 Admin API Key、正式 SMTP 或正式收件邮箱。
